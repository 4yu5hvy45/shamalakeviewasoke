# Shama Lakeview Asoke — Website Redesign Brief
## Design and build handoff for Beyond Branding Studio

## Project goal

Create a credible, conversion-focused hotel website concept for **Shama Lakeview Asoke Bangkok**. It should look and behave like a polished serviced-apartment hotel website, not a sparse AI-generated landing page.

Official website: https://www.shama.com/lakeview-asoke  
Accommodation: https://www.shama.com/lakeview-asoke/accommodation  
Special offers: https://www.shama.com/lakeview-asoke/special-offers

## Brand and visual direction

- Treat the supplied Shama logo and official property assets as the source of truth.
- Use a hospitality-first visual system: confident photography, a clear header, a recognisable booking area, readable room cards, practical information, and a detailed footer.
- Use the Shama brand palette as the primary palette. Keep the page warm, welcoming, and professional.
- Use an editorial serif for large headlines and a clean sans-serif for navigation, booking fields, room details, and body copy.
- Do not overuse glass effects, abstract gradients, tiny text, or excessive empty space.
- Do not fabricate client logos, awards, review scores, facilities, rates, or guest testimonials.

## Suggested homepage structure

1. Utility/offer strip — a concise current offer, with a direct link to the official offer page.
2. Header — official logo, Rooms & Suites, Facilities, Offers, Location, and a high-contrast Book Now button.
3. Hero — a real Shama property photo, clear headline about apartment-style living, one primary booking CTA, and one secondary explore CTA.
4. Booking module — check-in, check-out, room/guest selection, promo code if supported, and a working handoff to Shama's official booking engine.
5. Intro / property promise — explain the serviced-apartment experience in specific, accurate language.
6. Rooms and suites — accurate room names, sizes, approved photography, short descriptions, and links to official room details.
7. Facilities — pool, gym, indoor golf driving range, kids playroom, Wi-Fi, and other confirmed amenities.
8. Offers and packages — use the current official promotion copy and conditions; link to the appropriate official offer.
9. Neighbourhood and access — Asoke, nearby parks, shopping, convention centre, transit connections, and accurate distances only.
10. Gallery / guest information — approved images, contact, address, transport, policies, and FAQs.
11. Footer — property address, reservation number, navigation, and official social links if approved.
12. Persistent bottom CTA — a compact offer/book bar, responsive and accessible, that never obscures important content.

## Sticky bottom CTA concept

Suggested hierarchy:

- Left: Shama logo or compact property identifier.
- Centre: **“Up to 28% off*”** or a current approved offer headline.
- Supporting copy: “Book direct. Get more.”
- Actions: “View offer” and “Book now”.
- Link the offer CTA to https://www.shama.com/lakeview-asoke/special-offers and booking CTA to https://www.shama.com/lakeview-asoke.
- Add a readable qualification: “*Selected stays and member terms apply. Check official offer details.”
- Mobile: collapse the layout to the offer and one primary button; keep enough bottom padding on the page so content can scroll above the bar.

**Accuracy:** The official offers page has recently advertised up to 28% total savings on eligible stays, with conditions and booking/stay windows. Verify the live page immediately before publishing. Do not label it as a universal 25% discount.

## Booking integration — must be real

A date picker that only opens the homepage is a design mockup, not an integrated booking system.

Preferred order:
1. Use Shama's approved booking-engine URL or embed/integration, supplied by the property.
2. Pass check-in, check-out, occupancy, room count, and promo code only if the official engine supports the documented parameters.
3. If parameters cannot be passed, label the module clearly as a concept and send users to the official booking page without implying that selections were transferred.
4. Test the handoff on mobile and desktop. Do not collect payment or personal data in this concept page.

- [ ] Official Shama logo files (SVG/PNG), correct variants and clear space.
- [ ] Approved high-resolution property photos for hero, rooms, pool, facilities, and neighbourhood.
- [ ] Approved room names, sizes, occupancy, and feature lists.
- [ ] Current offer terms, valid dates, and any required disclaimer.
- [ ] Correct booking-engine link or integration instructions.
- [ ] Official contact details, social links, and property policies.
- [ ] Permission to use property assets in a speculative concept/pitch.

## Technical and QA requirements

- Responsive at 360px mobile, tablet, and desktop.
- Persistent CTA with fixed positioning, safe-area awareness, keyboard accessibility, and enough page bottom padding.
- Meaningful image alt text; avoid describing placeholder photography as actual property photography.
- Compress images and use modern formats where possible.
- Test navigation, booking links, offer links, date fields, focus states, contrast, and all external links.
- Keep the “concept / independent proposal” note visible until the client approves the design.
- Do not claim bookings, prices, or availability are live unless they are connected to the official system.
